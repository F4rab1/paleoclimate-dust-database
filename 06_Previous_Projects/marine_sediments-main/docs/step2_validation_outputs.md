# Step 2 Validation and Diagnostics Outputs

This note documents the additional quality-control outputs generated by the Step 2 pipeline.

## New Output Files

For each timestamped run (`step2_analysis/data/<timestamp>/`):

- `mapping_provenance_summary.csv`
- `integrity_validation_sample.csv`
- `integrity_validation_failures.csv`
- `integrity_validation_summary.txt`
- `u238auth_negative_diagnostics.csv` (also mirrored at `analysis_output/u238auth_negative_diagnostics.csv`)

For each successful site (`step2_analysis/data/<timestamp>/remapped_tables/<Site>/`):

- `<Site>_mapping_provenance.csv`
- `<Site>_AS_table.txt` (always produced for successful remaps, includes provenance references)

For sites with negative `AU238 (auth) [dpm/g]` (`step2_analysis/data/<timestamp>/analysis_output/`):

- `<Site>_validation_report.txt`

## Root-Cause Labels for Negative `U238auth`

`D3v1_01.py` assigns one deterministic label for each negative row:

- `LITHOGENIC_DOMINANCE`
- `SUSPECT_UNIT_MAPPING`
- `SUSPECT_COLUMN_MAPPING`
- `EDGE_NEAR_ZERO_BALANCE`
- `INSUFFICIENT_METADATA`

The global CSV includes row-level values and provenance pointers to the mapped source columns.

## Integrity Validation Scope

`validate_integrity.py` performs a stratified sample validation (default `10%`) across successful remapped sites.

Checks are grouped into:

- `unit_consistency`
- `mapping_accuracy`
- `sample_origin_clarity`

The summary file reports the sampled count and failure counts per check group.
